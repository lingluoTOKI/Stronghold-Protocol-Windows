# SQLite 休整期恢复

独立存储接口位于 `server/recovery/store.js`：put、fact、list、backup、flush、close。SQLite 位于独立工作线程，WAL + synchronous=FULL；每局保留当前和上一份完整快照，SHA-256 校验，提交结算后禁止回到 active。数据库文件只允许服务器账户访问，含重连凭证，不能公开下载或提交 Git。

## 启用与范围

使用支持 node:sqlite 的 Node 22.23.3 或 Node 24（两版本均已测试），设置 `SP_MATCH_RECOVERY=1`；默认关闭。默认路径 `runtime/matches.sqlite`，两服必须使用各自目录。仅主服原版普通对局（单人、多人及 AI 队友）接入；测试房、玩法插件子进程不启用。首次部署之前运行的旧进程没有存档能力，不能恢复那些旧对局。

## 保存及恢复

进入 PREP，完成本轮休整期起始效果后、AI 行动前保存一次；不会每秒保存。保存包括商店、棋盘、物品、共同卡池、玩家计数、随机流位置、开局日期、挑战资格和私密重连身份。SQLite 写盘不阻塞游戏主线程；进程异常中止时使用最近一次已提交的快照。

重启后暂停恢复房间的计时与操作，等待所有未退出的人类玩家明确点击“确认继续对局”。按原凭证认座位，不按昵称。恢复等待窗口为重启后的 24 小时；普通刷新和断线重连规则保持原状。休整期保存之后的操作和当轮战斗需要重做，不承诺任意时刻无损续接。

恢复使用存档中的商店和随机流，不重新抽选。恢复后商店刷新不能洗随机结果。开启 AI 托管先保存不可逆资格标记，关闭也不清除。永久退出记录也先写盘；若退出发生在快照之后，旧队伍状态不再安全，保留并报告该存档，等待人工处理。进入下一次休整期并保存后恢复正常。恢复不再执行 onPrepStart，避免重复赠送资源。

结算先将最终结果写为 finished，再发送结果和保存挑战奖励。挑战数据同时保存恢复结算收据，避免重复发奖；最终战报在重启后一天内可用原身份重取。finished 存档保留八天，绝不会回退到旧 active 快照。

## 兼容、失败与备份

存档校验整个对局代码与内容的兼容指纹。代码改变时默认拒绝自动恢复，原始存档保留；本版没有跨规则版本迁移器。因此发布更新仍应先排空现有对局，或明确接受中断；不能声称任意版本更新都能续接。

单份快照损坏时只对 active 尝试上一份；数据库损坏、未知版本、两份损坏、身份冲突均不覆盖原文件。健康接口的 recovery 字段提供启用状态、队列长度、错误数；详细错误写服务器日志。错误数非零不能按“可安全恢复”处理。只有成功保存过的房间才能恢复。

备份运行 `node tools/backup-matches.mjs /绝对路径/runtime/matches.sqlite /绝对路径/私密备份.sqlite`，或调用存储接口 backup(绝对路径)，SQLite 生成一致性副本，目标必须不存在。运行期间不要只复制主数据库文件而遗漏 WAL。数据库、挑战积分 JSON 和配置应一起备份到另一台机器。恢复旧备份前必须另存当前数据，不能覆盖新增成绩。

本版还未提供大屏“保存并暂停”维护按钮；正常运行期间的存档点是休整期入口，不是任意维护时刻。SQLite 恢复无法防止服务器磁盘整体损坏，异地备份仍必要。
