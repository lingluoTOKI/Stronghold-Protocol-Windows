# 游戏账号与群内 QQ 验证（实施约束）

状态：代码已实现并部署（2026-10-30），**功能未启用**。两服进程未重启，账号库未创建；机器人插件已重载、代码就绪。未经用户进一步同意不得重启两服。

## 身份与数据
- 两服共用账号（账号名、密码哈希），分服关联现有挑战身份，禁止覆盖已有绑定。
- 原有挑战恢复码只恢复原服的积分与成就身份，不自动成为全账号改密凭据。
- 全账号恢复码另行生成、仅保存哈希，使用后轮换；不可查询明文。
- QQ 主体以机器人实例与平台用户标识组合识别，不能使用昵称或消息中填写的 QQ 号。

## 群内绑定
1. 已登录游戏账号申请短期绑定挑战，挑战绑定当前浏览器的秘密凭据。
2. 机器人可信服务端上报实际发送者身份，浏览器才能读取待确认绑定。
3. 原浏览器确认后绑定；不接受群内消息直接完成绑定。
4. 码过期、已使用、多个发送者竞争或账号已有不同绑定时拒绝覆盖。

## 群内找回
- 必须先绑定，找回请求只能匹配原绑定主体。
- 不能让公开验证码本身变成改密能力，也不能将授权自动交给任意发起请求的浏览器。
- 采用游戏端与群端双向挑战确认，并明确提示仅确认自己刚在游戏发起的操作。
- 新密码仅在 HTTPS 游戏页提交；机器人只返回确认状态，不发送恢复码、密码或登录链接。
- 改密成功撤销旧会话及未完成找回请求；绑定/重置记录供管理员审计，公开大屏仅显示绑定状态。

## 实现与验证边界
- SQLite 事务保存账号与唯一关联，密码使用异步 scrypt；有界队列与账号/IP/机器人主体限流。
- 机器人桥须认证且防重放，浏览器写接口验证 Origin/CSRF，敏感响应 no-store。
- 测试覆盖抢码、过期、重复确认、跨服冲突、错误 QQ、改密会话失效、旧成绩不变。
- 本地验证后再准备部署；未经用户进一步同意不得重启两服。
