## 一、这次更新做了什么

相对线上正在运行的版本（build `7fc0606`，app 0.2.1），本次只有**两块实质改动**：

1. **档案串档修复**：大厅切到「原版」档案开局后，「确认本局信息」与干员调配不再错误显示莱茵生命盟约 / 莱茵干员；观战、断线重连同样修正。
2. **自选干员进盟约名单（对齐上游 0.2.1 条 26 / R21C）**：自选编队里尚未拥有的可选干员也显示在盟约展开名单中（暗色 / 禁用态），可点开看卡片；本扩展的「本局无法出现干员」红色禁用徽标保留。

版本号仍为 `0.2.1`（热修不改 `package.json` 版本），通过公告 `0.2.1-rhine.2` 与部署 build 号区分。

## 二、档案串档修复（根因与改动）

### 现象

大厅明明切到了**原版**档案，开始对局后「确认本局信息」里仍出现**莱茵生命**盟约，干员调配里也混着莱茵干员；而服务端实际是按原版数据模拟的——画面与真实对局不一致。

### 根因

对局广播 `m.public(publicView)` **不携带** `rhineEnabled / dataProfile` 字段。前端在对局态调用 `prepareDataProfile(undefined)` 时，被 `dataProfileId` 的默认值判定为 **rhine**，于是开局一瞬间把大厅选择的「原版」覆盖回「莱茵」。服务端其实按原版数据正常模拟，**纯前端档案标志在开局时丢失**；观战 / 重连走同一广播路径，也会被带偏。

### 改动文件（服务端 3 + 前端 3，已在提交 `b2d9a71`）

| 文件 | 改动 |
|---|---|
| `server/match/Match.js` | 对局构造时**固化** `this.dataProfile` / `this.rhineEnabled`，整局不再随全局默认漂移 |
| `server/match/match/views.js` | `m.public` 每帧输出 `rhineEnabled` 与 `dataProfile`，让前端拿到本局真实档案 |
| `server/lobby.js` | ownership / diy 编队校验**按房间档案取数**，不再全局默认莱茵 |
| `public/js/main.js` | `m.public` 缺字段时**回退 `room.rhineEnabled`**，不再无条件默认莱茵 |
| `public/js/ui/dataProfile.js` | `profileFromState` 对局态同样回退房间标志 |
| `public/js/data.js` | `useData` 响应 `PROFILE_CHANGE`，即使数据已缓存，切档也触发重渲染 |

效果：原版房 = 纯上游 0.2.1（无莱茵盟约 / 干员 / 科研装置）；莱茵房才出现莱茵内容；观战与断线重连按本局真实档案显示。

## 六、部署与运维

- 部署路径：`/root/stronghold`（阿里云 ECS，公网 `101.132.104.41`，域名 `game.lingluotoki.dpdns.org`）。
- 运行方式：systemd 服务 `stronghold.service`，`WorkingDirectory=/root/stronghold`，`ExecStart=/usr/local/bin/node server/index.js`，端口 **3000**。
- 本次含**服务端改动**（`Match.js / match/views.js / lobby.js`），部署后**必须** `systemctl restart stronghold.service`（光刷新前端不够）。
- **素材铁律**：部署包不含 `node_modules` 与 `public/assets`；服务器上必须 `cp -a` 保留旧目录这两者，**禁止**对素材目录做镜像 / 删除操作。
- 部署步骤：备份现网 → 上传代码包（server/public/shared/tools/scripts/data + announcements.json + 文档）→ 对改动的 server 文件 `node --check` → 原子切换（stop / 替换 / start）→ `curl http://127.0.0.1:3000/healthz` 验证 → 外网硬刷新页面。
- 回滚：部署前备份到 `/root/stronghold-backups/`；异常时用备份目录还原并重启即可。
