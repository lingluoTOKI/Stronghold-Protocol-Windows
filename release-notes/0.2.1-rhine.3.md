## 一、这次更新做了什么

相对上一版（提交 `30afd93`），本次共改 10 个代码文件 + 新增 1 个运维页面，提交 `3703c7d`：

1. **【根因修复】浏览器战斗丢失 `setSimData`，导致盟约机制 / 叠层在战斗中整体失效**——阿戈尔「鱼吃鱼」吞噬、拉特兰击杀与技能叠层、多个盟约战斗内效果集体不生效的真正原因。
2. **服务端战斗数据按房间档案兜底**：断线接管、bot 演练、服务端校验战斗不再全局默认读到莱茵档案。
3. **全模式开启战斗内盟约叠层**（服主明确要求）：联合作战、BOSS 回合、意图预览、bot 演练现在都能在战斗中叠层（上游原本只在普通战斗开启）。
4. **招募类物品不再被空 roll 吞掉**：简易通讯机 / 寻呼模块 / 拟态物质在低等级 roll 不到同阶级干员时保留物品。
5. **运维**：`/healthz` 加 CORS、新增在线玩家查询与踢人管理接口、新增双服务器监控大屏 `monitor.html`。

版本号仍为 `0.2.1`（热修不改 `package.json` 版本），通过公告 `0.2.1-rhine.3` 与部署 build 号区分。

## 二、根因：浏览器战斗丢失 `setSimData`（决定性）

### 现象

群友反馈：阿戈尔「九回合 0 层」「鱼不吃鱼了」、拉特兰「圣葬人杀了人一直 0 层」、靠技能叠层的盟约在战斗中全部叠不上；多个盟约战斗内效果异常。

### 根因

浏览器战斗默认 `clientCombat=true`（战斗在各玩家浏览器里本地确定性模拟，服务端只转经济与回合）。浏览器端 `content/support` 的全局 `gameData()` 依赖一个数据 shim：必须先调用 `simdata.setSimData(raw)` 把本局档案数据注入，`getSimData()` 才取得到内容。

纯上游 0.2.1 的 `public/js/battle/runner.js` 在加载浏览器模拟时有两行关键初始化：

```js
simdata.setSimData(raw)   // 注入本局档案数据
support.setGameData(null) // 清掉可能残留的全局数据，改走 shim
```

本扩展在 vanilla / rhine 双档案重构时，**把这两行整体弄丢了**（全 `public/` 目录 grep `setSimData` 零命中）。后果链：

1. 从未 `setSimData` 注入 → `getSimData()` 返回空 → `getData()` 落到 `{}`；
2. `bondBb(盟约id)` 全部 `undefined`、`coreBondIds()` 返回空集；
3. 拉特兰 `installLaterano` 执行 `bb.base_ammo_percent`、`num(bb.atk_per_consume,0)` 时抛 `TypeError`，被 `content/index.js` 的 try/catch 吞掉，**整个拉特兰盟约安装失败**；
4. 阿戈尔 `installEgir` 因多处可选链 + 伤害默认值不直接崩，但吞噬 / 叠层机制数据缺失而受损。

这解释了为什么多个彼此独立的盟约在战斗中「集体失效」——它们共用同一份没被注入的数据。

### 前端改动（`public/js/battle/runner.js`）

- `loadBrowserSim` 的动态 import 从 `[spec, simdata]` 改为 `[spec, simdata, support]`（补入 `content/support/index.js`）；
- 组装出 `raw` 后新增 `applyProfile()`：调用 `simdata.setSimData(raw)` 与 `support.setGameData(null)`，并立即执行一次；
- 返回对象从 `{spec, ds}` 扩展为 `{spec, simdata, support, raw, applyProfile, ds}`；
- **关键**：`onStart` 中 `createBattleFromSpec` 之前调用 `sim.applyProfile()`。因为双档案用 `simPromises` Map 缓存两份 sim，切档后第二次开局不会重跑 `loadBrowserSim`，必须每场战斗开始前重设全局数据，防止 vanilla / rhine 串档。

## 三、服务端战斗数据按房间档案兜底（`withGameData`）

服务端在断线接管、bot 演练、`SP_VERIFY` 跑原版战斗时走 headless 模拟，其全局 `gameData()` 原本懒加载 `data/`（即莱茵档案），原版房在这些路径下仍可能读到莱茵数据。

利用现成的 `server/sim/content/support/dataScope.js`（`withGameData(data, fn)`，模块级同步上下文，支持嵌套保存恢复）：

| 文件 | 改动 |
|---|---|
| `server/sim/battle/hooks.js` | 顶部 import `withGameData`；`BattleHooks` 新增 `_withData(fn)`，把事件 emit 的 handler 执行与 `_safe` 回调都包进 `this._withData(...)`（有 `battle.data` 时按本局档案，无则透传） |
| `server/sim/content/index.js` | import `withGameData`，把整个 `installContent` 函数体包进 `withGameData(battle.data, () => { … })` |

这样服务端一切战斗内容安装 / 事件触发都在本局档案的数据上下文中执行，与前端修复形成双保险。

## 四、全模式开启战斗内盟约叠层（服主明确要求，与上游设计有别）

上游 0.2.1 **官方设计**是：盟约战斗内叠层（`layerGainsEnabled`）只在**普通战斗**开启；联合作战（联防）、BOSS 回合、最终突击等模式刻意关闭（相关代码注释明确）。群友在联合作战里反馈叠不上，部分本是这一官方行为。

服主明确要求「不管了必需叠层」，本次把该开关在所有模式强制打开：

| 文件 | 位置 / 改动 |
|---|---|
| `server/sim/Battle.js` | `layerGainsEnabled` 默认从 `this.kind === 'normal'` 改为 `true` |
| `server/match/match/unitePhase.js` | 联合作战：`false → true` |
| `server/match/match/bossRounds.js` | BOSS 回合：`false → true` |
| `server/match/match/intents.js` | 意图预览：`!bossRound → true`，并删除因此不再使用的 `bossRound` 变量 |
| `server/match/bot.js` | bot 演练：`false → true` |

> 注意：`server/sim/.../fields.js` 里服务端对 `spec.flags.layerGainsEnabled === false` 的校验保留（防作弊）；现在所有下发的 spec 都是 `true`，该校验不再触发。
>
> 这是**本改编版相对上游的有意偏离**，纯原版备用服（116.62.39.28，上游冻结 0.2.1）**不做**此改动，保持官方行为。

## 五、招募类物品 roll 空时不再被吞（`server/match/builtinMeta.js`）

简易通讯机（电话）、寻呼模块、拟态物质三个物品，使用时按使用者所属盟约 roll 同**阶级（tier）**干员。原逻辑在商店等级低、roll 出 0 名符合条件干员时，仍把物品消耗掉（群友反馈「电话和寻呼模块放在梅尔身上会被吞掉」）。

本次给三个 handler 统一加：**一个干员都没 roll 出来时设 `ev.keep = true`**，物品保留不消耗，等商店等级提升后再用即可正常生效。

> 群内曾误传为「星级」问题，实际匹配口径是**阶级 tier**，不是星级。
